# Seguimiento de cambios de Spark

Las historias académicas previas son antecedentes, no un límite que impida una
modernización autorizada del producto. No inventar IDs, reasignar integrantes ni
actualizar Excel o sprints al editar código. Una petición explícita del usuario
define el alcance actual; registrar problema, cambio, evidencia y pendientes.

Usar ramas y PR según git-commit-conventions. No publicar ni desplegar sin autorización.
No iniciar funciones que requieran capturar datos nuevos en otros componentes sin
acordar primero el contrato, privacidad y alcance con el propietario.
